# 实施路线（外部评估摘要）

这份路线来自一次外部大模型的方案评估（ChatGPT），后来成为项目的实施骨架。原文比这里长，以下保留可执行的部分。

## 总原则

先只读召回，再可靠固化，最后接情感。每个阶段都能独立运行、测试、回滚。**不要同时开发三层。**

## 阶段 0 · 准备与基线

先不写功能代码，只确认宿主行为：

- `systemPrompt.section` 的执行时机、消息通道、优先级；
- `agent/pre-step` 与 `assemble()` 的先后、`step === 1` 是否符合预期；
- `createUserMessage` 与 `source.kind` 的真实类型；
- 记忆文件的路径、编码、换行、写盘守卫；
- 对话日志的倒序规则、能否拿到稳定消息 ID；
- 召回超时后原对话是否不受影响。

交付物：宿主行为记录、备份、可回滚的分支。

## 阶段 1 · P0 记忆召回

- **P0a**：常驻只放「记忆使用协议」，≤800 字，不重复人格段。若实测现有提示已覆盖，可暂缓。
- **P0b**：只读召回，`agent/pre-step` + `step === 1`；中文 2-gram + IDF + 词频 + 长度归一；top 3；覆盖率与相对阈值双重过滤；前置注入、带来源标记、150 ms 超时、失败静默、写 `recall.log`。
- **不做**：embedding、SQLite、UI 面板。

验收：Recall@3 ≥ 85%（50–100 条人工 query）；无关查询不硬注入；失败不影响对话；同轮不重复注入；前置注入不改变真实用户消息。

## 阶段 2 · P1 记忆固化

第一版只写一个**独立的派生文件**（`structured.jsonl`），不动日记/状态/生长记录：

```json
{ "id", "type", "fact", "source_id", "quote", "status", "created_at", "confidence" }
```

固化顺序：读快照 → 按稳定 ID 选未处理内容 → LLM 提取候选 → 验引文/字段/冲突 → 重读核对指纹 → 安全写入 + 备份 + 批次记录。

硬规则：

- LLM 调用放在写盘守卫之外；
- 引文必须能在来源中逐字找到；
- **引文存在不等于事实成立**，否定、时间、主体、状态要单独校验；
- 冲突标为待审或新旧关系，不擅自覆盖；
- 用稳定 ID + 批次 ID 实现幂等，不靠行号；
- 写前发现文件变化就拒绝并重处理；
- 不写事件流。

## 阶段 3 · P2 情感状态

状态文件 `affect/state.json`：`valence`（-1..1）、`arousal`（0..1）、`trigger`（事件 ID / 类型 / 时间）、`updated_at`。

第一版用规则表，不调 LLM：感谢升 valence、不满降 valence、闲聊升 arousal、严肃求助降玩笑、任务成败更新并留原因、长时间无消息**不**解释为负面。

限幅 + 向基线衰减 + 事件去重（防一次成功不断累加）。

接入顺序：先写单测 → 映射成一句语气提示 → 只接 `systemPrompt` 一个消费者 → 验证不覆盖用户需求与人格 → 稳定后再接桌宠动画 → **不改 selfwake 的闸门**。

## 关键提醒

原文里最值得记住的一句：**先让角色稳定地找回相关历史、正确识别旧事实，并在没有记忆时坦诚地承认不确定**——这比让它自动整理经历、产生情绪都更重要。
