### 零宽字符绕过注入加固 — P1，已修（`a43c268`）

- **现象**：`hardenRecallText` 逐行按 `^([ \t]*)` 认行首，而 U+200B 不算空白。
  每行开头塞一个零宽空格，伪造的 `[memory-recall]` 来源行、终止语、`##` 标题可整行穿透。
- **修复**：入口先 `replace(INVISIBLE_RE, '')` 清掉不可见字符，再逐行匹配。
- **验证**：三行伪造结构（来源行 / 终止语 / Markdown 标题）实测全部被转义。

### 非字符串 query 抛 TypeError — P2，已修（`a43c268`）

- **现象**：`recall(cfg, 123)` 抛 `TypeError: (s || "").replace is not a function`。
- **修复**：`grams()` 前统一 `typeof query === 'string' ? query : String(query ?? '')`。

## 未修复（明确待办，不要当成已解决）

### 1. 被淘汰事实可从 autocapture 通道原样召回 — P1

- **现象**：同一段旧结论，对话正文标 superseded 后不再返回，但自动捕获的副本照样进 top-3 并被注入。
- **根因**：`index.js` 把捕获记录塞进候选池时只带 `id/src/line/text`，没有 `contentId` 也没有 `sourceId`；
  `status.mjs:62-109` 的 `resolveEntryStatus` 只认这三种身份，全落空返回 null；`status.mjs:145-147` 在状态表健康时把 null 一律当可召回。
- **方向**：autoCapture 落盘时写入对应对话的 `content_id/source_id`，或在 loadEntries 用内容指纹反查状态表。

### 2. 内容微调 + 行号漂移后 superseded 复活 — P1

- **现象**：只改小节标题（正文一字未动）并在文件上方插两行，已淘汰的结论重新被召回。
- **根因**：标题一改内容哈希失效，行号一漂来源坐标失效，身份全丢于是按「未知条目」放行。
  `status.mjs` 的 `idDrift` 只统计不拦截。
- **方向**：内容身份只对正文计算（不含标题行，参考 `summary.mjs` 里 `contentId: idOf(body)` 的修法）；
  或在状态表已覆盖该来源文件时，把无身份条目按 unverified 处理。
- **注意**：这条和「导航行号漂移复活」是同一类漏洞的两个通道。导航侧已修，召回侧尚未。

### 3. 无答案查询被判 answer 并注入 — P1

- **现象**：冻结集 24 条无答案样本里 2 条拿到 `verdict=answer`，证据强度 0.657 / 0.774。
- **根因**：`abstain.mjs:167-179` 的硬门槛只看 `matched/coverage/density`，
  命中的是旁支 2-gram，没有「命中片段是否回答了问题」的检查。
- **方向**：给 answer 增加「查询实词须出现在同一句/子句」或 matched 集中度约束。
- **约束**：必须在**新留出集**上验证，不要拿冻结集调阈值。

### 4. 「污染 / 过期」指标测的不是 superseded 泄漏 — P2

- **现象**：冻结集报 3 条污染，实际 0 条来自被淘汰记录。
  1 条是被正确返回的新条目正文自己引用旧词，另 2 条是音乐/视频缓存互相串台。
- **根因**：`scripts/eval-report.mjs` 用「返回文本包含 forbid 子串」判污染，不看条目身份/状态。
- **方向**：污染按 `entry.id/content_id` 对照状态表判定，而不是子串；顺带审一遍 forbid 标签。
